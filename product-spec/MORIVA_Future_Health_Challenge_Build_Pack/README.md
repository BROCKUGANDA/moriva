# MORIVA — Future Health Challenge Build Pack

**Tagline:** Notice earlier. Find the right support.

This pack contains the product specification, terminal-agent execution contract and editable brand assets for a proposed privacy-first wellbeing recognition and care-navigation platform aligned to the Future Health Digital Innovation Challenge 2026.

## Files

- `PRD.md` — full product requirements document (also in `docs/01_MORIVA_PRODUCT_REQUIREMENTS_DOCUMENT.md`).
- `docs/02_MORIVA_STAFF_ENGINEER_IMPLEMENTATION_PROMPT.md` — sequential staff-engineer / forward-deployed-engineer execution prompt.
- `docs/REFERENCES.md` — official and standards references.
- `brand/BRAND_GUIDELINES.md` — name, positioning, logo use, typography, colours, iconography and interaction styling.
- `brand/moriva-logo-primary.svg` — editable SVG wordmark.
- `brand/moriva-mark.svg` — editable mark.
- `brand/moriva-logo-reversed.svg` — reversed wordmark for dark surfaces.
- `brand/favicon.svg` — SVG favicon/app mark.
- `brand/moriva-brand-board.png` — rendered brand board.
- `brand/moriva-generated-mark-concept.png` — generated raster concept; not the master vector logo.
- `demo_assets/synthetic_demo_seed.json` — fictional demo records only.

## Using this with a terminal coding agent

1. Copy the `docs/` and `brand/` folders into the application repository.
2. Copy `PRD.md` to the repository root or rename it `docs/PRD.md`.
3. Open `docs/02_MORIVA_STAFF_ENGINEER_IMPLEMENTATION_PROMPT.md` in the coding agent.
4. Instruct the agent to begin at Phase 0 and follow the execution gates in order.
5. Do not allow the agent to skip clinical safety, consent or role-isolation tests.

## Important clinical, privacy and legal boundary

MORIVA is a working brand and prototype concept, not a cleared trademark, licensed healthcare provider, clinically validated system, approved medical device or production care service. Use synthetic data only in the hackathon prototype. Do not process live patient information or represent simulated provider/referral activity as real. Clinical content, instrument rights, thresholds, translations, local provider data, emergency contacts, hosting/data residency and legal/regulatory classification require named human review before a live pilot.
